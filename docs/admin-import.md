# 와포북 엑셀 등록과 SOOP 프로필 검수

작업 브랜치: `feat/admin-xlsx-soop-profiles`. 운영 배포 대상이 아니며 `main`에는 병합하지 않습니다.

## 사용 가능한 기능

현재 프로필 사진은 제공된 공개 이미지 URL 규칙으로 직접 로드를 검증한 뒤 원본 URL을 연결할 수 있습니다. 아래의 공식 API 조사/실패 기록과 OAuth workflow 설정 대기는 별도 경로의 과거 검토 기록이며, 현재 이미지 URL 로더의 비활성 상태를 의미하지 않습니다. LIVE/닉네임 API는 여전히 미연동입니다.

관리자 → **엑셀 일괄 등록**에서 양식을 내려받고 `.xlsx`를 올립니다. 전용 양식은 [다운로드 파일](../downloads/wapobook-admin-template.xlsx)에 있습니다.

- 모험가 정보: 버튜버명, 캐릭터명, 레벨, 종족, 직업, 전문화, 역할, 소속 길드, SOOP 방송국 주소, 대표 캐릭터.
- 길드 정보: 길드명, 길드장, 전체 길드원 수, 길드 소개, 확인일.
- 이전 시즌 참여 기록: 버튜버명, 참여 여부, 레벨, 직업, 전문화, 레이드 기록.
- 입력 방법 안내: 각 열과 등록 순서, 보존 규칙, 사진 동기화 절차.

빈 양식이며 예시 인물을 데이터에 등록하지 않습니다. 사진 입력 열은 없습니다. 직업·종족·역할·참여 여부·대표 캐릭터 드롭다운은 2행부터 Excel 마지막 행(1,048,576행)까지 적용됩니다. 표의 마지막 셀에서 Tab 또는 행 삽입으로 행을 늘릴 수 있습니다. 150명 제한은 없으며 180명 실제 XLSX 업로드·병합·재업로드를 Chromium에서 검증했습니다. 일반 파일은 20MB, 압축 해제 합계는 80MB 안전 한도입니다. 수식·매크로·암호화·포함 개체는 거부합니다.

## 저장·보존 규칙

1. 업로드하면 미리보기만 만듭니다. 원본 데이터와 localStorage에는 쓰지 않습니다.
2. 길드를 먼저 연결하고 SOOP 계정 ID → 정확히 일치하는 버튜버명 순서로 기존 모험가와 연결합니다. 이름·계정 충돌이나 다중 일치는 실패로 보고합니다.
3. 동일 캐릭터명은 기존 캐릭터에 연결하고 없는 캐릭터만 추가합니다. 기존 비어 있지 않은 값, 대표 캐릭터와 사진은 자동 변경하지 않습니다. 변경은 기존 관리자 수정 화면을 사용합니다.
4. 길드 참조 오류·잘못된 선택값·잘못된 URL·수식 등은 구체적인 오류로 보고합니다. 실패 행은 병합에서 제외합니다. 중복 업로드는 같은 정보를 재등록하지 않습니다.
5. `성공 항목 병합 승인`을 눌러야 반영됩니다. 승인 전 원본 JSON 백업을 내려받으며 기존 `forever-azeroth-v1` 키에 저장합니다. 다른 탭에서 데이터가 바뀌었으면 재검수를 요구합니다. 저장 실패 시 메모리 상태를 되돌립니다.
6. `fa-favs`, BGM 저장값, 슬롯, 이벤트·연대기·제보 및 원래 데이터의 미지 필드는 변경하지 않습니다.

**중요한 공개 범위:** 기존 사이트에는 로그인·서버 DB가 없습니다. 엑셀로 병합한 정보는 현재 브라우저에서 도감·검색·상세 화면에 즉시 반영되지만 다른 방문자의 브라우저로 전파되지 않습니다. 이 작업은 기존 저장 방식을 임의로 바꾸거나 현재 운영 데이터를 수집·삭제하지 않습니다. 전체 방문자에게 공개하려면 인증된 서버 저장 또는 별도의 공개 데이터 배포 설계가 필요합니다. 백업/조회 요청 파일에는 현재 브라우저의 등록 정보만 포함됩니다.

## OAuth API를 통한 관리자 승인형 사진 동기화 (별도 설정 대기)

아래 실행 기반은 구현·오프라인 검증했지만 실제 API 연결은 미완료입니다. `sync/soop-provider.json`은 비활성 상태이고 임의 엔드포인트가 들어 있지 않습니다.

1. SOOP 개발자 앱에서 공식 프로필 API 문서, 필요한 권한과 이용 조건을 확인합니다. 계정 ID와 실제 방송국 프로필 이미지 필드가 있는 응답이어야 합니다. 해당 API가 제공되지 않으면 이 자동화 방식은 사용하지 않습니다.
2. 검토 근거 URL/승인 기록, HTTPS 공식 Open API 엔드포인트와 정확한 응답 필드를 공급자 설정에 명시합니다. 인증 헤더는 확인된 공식 문서에 맞춰 `secretHeaders`에 `{ "헤더명": { "env": "SOOP_API_TOKEN", "prefix": "문서상 접두어" } }` 형태로 설정합니다. 헤더명·접두어를 추측하지 않습니다. 토큰은 GitHub Secrets에만 보관합니다.
3. 저장소 Settings → Environments에 `soop-profile-sync`를 만들고 **Required reviewers**를 설정합니다. 환경 변수 `SOOP_SYNC_APPROVED=true`는 검토 완료 후에만 설정합니다. 이 변수만으로 Required reviewers가 자동 구성되지는 않습니다. 현재 저장소의 환경 설정·Secrets는 변경하지 않았습니다.
4. GitHub의 `Review SOOP profile URLs` workflow를 `pilot`으로 수동 실행합니다. 이 기능을 아직 main에 배포하지 않았으므로 기본 브랜치에서 바로 실행할 수 있다고 보장하지 않습니다. 승인된 테스트 저장소/브랜치에서 운영 검토 후 실행합니다. 먼저 제공된 5개 계정 모두의 실제 프로필 조회가 성공해야 합니다.
5. 결과 아티팩트에서 원본 방송국과 사진을 관리자 눈으로 확인합니다. 성공한 보고서를 `sync/reviews/` 아래에 커밋합니다. 공급자 설정이 바뀌면 시험을 다시 해야 합니다. 보고서는 같은 설정으로 7일 이내 생성된 5개 성공 결과여야 합니다.
6. 관리자에서 사진이 없는 모험가만 `사진 조회 요청 JSON 다운로드`로 내보냅니다. `sync/requests/` 아래에 요청 파일을 올리고 `batch` 수동 실행 시 요청 경로와 시험 보고서 경로를 지정합니다. 인원을 150명으로 제한하지 않습니다. 작업 시간 제한은 90분이므로 매우 큰 명단은 나누어 실행합니다.
7. 결과 JSON은 아티팩트로만 생성되며, workflow는 웹사이트 데이터나 main을 수정하지 않습니다. 관리자에서 결과 JSON을 업로드하고 **프로필 원본 URL** 연결 결과를 검수·승인해야 사진이 적용됩니다. 기존 사진이 있으면 `중복 / 기존 사진 유지`, 이미지가 없으면 `이미지 없음`, 요청 오류는 `실패`로 표시합니다. 기본 이미지와 수동 URL 등록을 유지합니다.

조회기는 요청 간격 최소 2초, 일시 오류 2회 재시도(총 3회), 429 Retry-After(최대 60초), 최대 24시간 URL 캐시, 중복 요청 제거를 적용합니다. 401/403 뒤에는 추가 외부 요청을 중단합니다. 계정 ID 응답 일치와 프로필 전용 이미지 경로를 확인하며 이미지 바이트는 저장하지 않습니다. HTTP 리디렉션·비 HTTPS·다른 호스트는 허용하지 않습니다. 현재 허용 목록은 SOOP 공식 Open API 호스트와 프로필 이미지 호스트뿐입니다. API가 다른 공식 CDN을 반환하면 문서·이용 조건 확인 후 검수하여 허용 목록과 테스트를 수정해야 합니다.

## 추가 공식 문서 조사 및 수동 등록 검증 (2026-10-22)

사용자가 제공한 [broad-stream](https://developers.sooplive.co.kr/docs/api/broad-stream), [broad-watch](https://developers.sooplive.co.kr/docs/api/broad-watch)를 직접 열람하고 공식 도메인의 사용자·방송국·프로필·stationinfo 관련 문서를 추가 검색했습니다. 두 본문 모두 작업 환경의 CONNECT 단계에서 403으로 차단됐으며 웹 열람 도구도 본문을 제공하지 못했습니다. 개발자 사이트 첫 화면은 제목만 확인할 수 있었습니다. 따라서 아래를 구분합니다.

| 조사 항목 | 확인 결과 |
|---|---|
| 두 문서가 프로필 조회와 관련 있는지 | 본문 접근 불가로 미확인. 경로 이름만으로 송출·시청 전용이라고 확정하지 않습니다. |
| ID로 타 방송국/사용자의 프로필을 조회하는 공식 API | 공식 명세에서 확인하지 못했습니다. API가 없다고 단정하지 않습니다. |
| 두 API 응답의 프로필 이미지 URL 포함 여부 | 응답 스키마 미확인. 썸네일 필드를 프로필로 취급하지 않습니다. |
| 사용자 인증/승인 Scope | 해당 API별 인증 방식·권한명·조회 대상 범위를 미확인 상태로 둡니다. |
| 150명 이상 일괄 사진 조회 | 임의 계정 조회 허용 범위·호출 한도·이미지 외부 사용 조건 미확인으로 보류합니다. 엑셀 180명 등록 검증과는 별개입니다. |

추가 검색의 비공식 사용 사례는 SOOP의 공식 API 명세나 이용 허가로 간주하지 않았습니다. 특히 로그인한 본인 정보가 반환되는 API가 있더라도 관리자 토큰으로 타인 150명의 정보를 조회할 수 있다는 뜻은 아닙니다. 허용된 조회 방법을 확정하지 못했으므로 공급자 설정은 계속 비활성이고 인증·수집 실행은 하지 않았습니다.

수동 등록은 관리자 → 엑셀 일괄 등록 → **사진 수동 등록·수정**에서 모험가를 선택하고 확인한 HTTPS 프로필 이미지 URL을 입력하여 저장합니다. 기존 모험가 수정 화면도 계속 사용할 수 있습니다. 사진 URL만 갱신하며 저장 실패 시 이전 값을 복구합니다. 직접 작성한 사진은 자동 조회 결과나 엑셀 재업로드로 덮어쓰지 않습니다. 수동 URL 등록·재접속 후 유지·180명 재업로드 후 사진 보존을 실제 Chromium UI로 검증했습니다. 업로드 파일과 시험용 URL은 격리된 브라우저에서만 사용했습니다.

수동 등록도 현재 브라우저 저장 범위가 유지됩니다. 원본 사진 파일 업로드/서버 저장 기능이나 모든 방문자에게의 공개 배포를 새로 추가한 것은 아닙니다. main/운영 홈페이지는 변경하지 않았습니다.


## 스트리머 ID를 이용한 두 종류의 정보 연결

프로필 사진·닉네임과 LIVE 상태·제목·썸네일·시청자 수·카테고리를 모두 스트리머 ID에 연결하는 방향으로 정했습니다. 엑셀의 `SOOP 방송국 주소` 열에는 URL 대신 계정 ID만 넣어도 기존 방송국 URL로 정규화됩니다. 버튜버 표시 이름은 유지하며 다른 계정이 같은 이름이라는 이유로 연결하지 않습니다.

관리자 `SOOP ID 조회 대상 다운로드`는 등록된 계정의 프로필/닉네임/LIVE 조회 요구를 JSON으로 내보냅니다. 중복 계정·잘못된 주소·미등록 계정은 검수 목록에서 구분하며, 기존 사진이 있는 계정의 사진 교체는 요청하지 않습니다. 이 파일은 **조회 대상을 준비하는 파일**이며, API 응답이나 실제 수집 완료 결과가 아닙니다. 기존 사진 전용 workflow의 입력 파일과 스키마가 다르며 해당 workflow에 바로 넣지 않습니다. 아직 이 파일을 자동 조회하는 작업은 연결하지 않았습니다.

`user/stationinfo`, `validate/live/status`는 사용자가 제공한 명세에 토큰만 있고 대상 ID 지정 항목이 없습니다. `broad/list`의 ID와 일치시키는 방식이 후보이지만, 해당 목록 API의 인증·조회 범위·호출 조건은 아직 미확인입니다. 따라서 현재 버전은 계정 ID 인식과 조회 대상 검수까지만 추가하며, 공식 권한이 확인되기 전에는 실제 API 호출·LIVE 표시·프로필 자동 변경을 활성화하지 않습니다. 라이브 썸네일은 프로필 사진으로 사용하지 않습니다.


## 공개 프로필 이미지 URL 연결 (2026-10-22 추가)

사용자가 실제 사례에서 복사한 원본은 `https://profile.img.sooplive.co.kr/LOGO/ji/jingburger1/jingburger1.jpg`입니다. 이 주소의 구조를 사용해 `https://profile.img.sooplive.co.kr/LOGO/{ID 앞 두 글자}/{ID}/{ID}.jpg` 후보 URL을 만들고, 브라우저의 Image 로드 성공과 실제 크기를 확인한 경우에만 미리보기에 연결합니다. URL 패턴을 SOOP의 문서화된 영구 API 계약으로 간주하지 않습니다. 다른 계정에서도 반드시 존재한다고 가정하지 않으며 실패 시 기존 기본 이미지와 수동 등록을 유지합니다.

관리자에서 엑셀을 업로드한 뒤 **ID로 프로필 사진 조회**를 누릅니다. 엑셀 저장 전 미리보기의 신규 모험가 또는 이미 등록된 모험가 중 사진이 없는 계정들을 순서대로 확인합니다. **방송 여부는 조회하지 않으며, 방송 중인 목록에도 의존하지 않습니다.** 기존 이름과 사진은 유지합니다. 조회 결과 확인 후 병합 승인을 눌러야 기존 저장소에 적용됩니다. 엑셀을 먼저 저장한 경우에도 같은 버튼으로 조회할 수 있습니다.

이미지 파일을 다운로드해 재배포하지 않고 원본 URL만 저장합니다. OAuth 토큰과 방송 조회 API는 사용하지 않습니다. 브라우저의 기본 이미지 로딩을 이용하므로 CORS용 우회 프록시도 사용하지 않습니다. 요청 간격은 계정 간 최소 1초, 실패 시 2초 후 1회 재시도, 8초 타임아웃, 취소 기능을 제공합니다. 성공한 URL과 확인 시각만 별도 `fa-soop-profile-url-cache-v1`에 최대 24시간 캐시하며, 원래 데이터 키와 즐겨찾기 구조는 유지합니다. 캐시 저장 실패는 원본 데이터 저장에 영향을 주지 않습니다.

앞서 제공된 5개 ID의 새 이미지 URL도 실제 접속을 시도했지만 이 작업 환경에서는 모두 CONNECT 403으로 차단됐습니다. 따라서 실제 SOOP 이미지 조회 성공을 주장하지 않습니다. 모의 이미지 응답을 사용한 Chromium 검사에서는 온라인/오프라인 두 계정 모두 사진 조회·검수·저장·재접속 유지가 동작하고 기존 사진은 조회·덮어쓰기되지 않는 것을 확인했습니다. 이 테스트는 실제 SOOP 접속 검증과 구분합니다.
