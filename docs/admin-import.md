# 와포북 엑셀 등록과 SOOP 프로필 검수

작업 브랜치: `feat/admin-xlsx-soop-profiles`. 운영 배포 대상이 아니며 `main`에는 병합하지 않습니다.

## 사용 가능한 기능

관리자 → **엑셀 일괄 등록**에서 양식을 내려받고 `.xlsx`를 올립니다. 전용 양식은 [다운로드 파일](../downloads/wapobook-admin-template.xlsx)에 있습니다.

- 모험가 정보: 버튜버명, 캐릭터명, 레벨, 종족, 직업, 전문화, 역할, 소속 길드, SOOP 방송국 주소, 대표 캐릭터.
- 길드 정보: 길드명, 길드장, 전체 길드원 수, 길드 소개, 확인일.
- 이전 시즌 참여 기록: 버튜버명, 참여 여부, 레벨, 직업, 전문화, 레이드 기록.
- 입력 방법 안내: 각 열과 등록 순서, 보존 규칙, 사진 동기화 절차.

빈 양식이며 예시 인물을 데이터에 등록하지 않습니다. 사진 입력 열은 없습니다. 직업·종족·역할·참여 여부·대표 캐릭터 드롭다운은 2행부터 Excel 마지막 행(1,048,576행)까지 적용됩니다. 표의 마지막 셀에서 Tab 또는 행 삽입으로 행을 늘릴 수 있습니다. 150명 제한은 없으며 180명 실제 XLSX 업로드·병합·재업로드를 Chromium에서 검증했습니다. 일반 파일은 20MB, 압축 해제 합계는 80MB 안전 한도입니다. 수식·매크로·암호화·포함 개체는 거부합니다.

## 저장·보존 규칙

1. 업로드하면 미리보기만 만듭니다. 원본 데이터와 localStorage에는 쓰지 않습니다.
2. 길드를 먼저 연결하고 SOOP 계정 ID → 정확히 일치하는 버튜버명 순서로 기존 모험가와 연결합니다. 이름·계정 충돌이나 다중 일치는 실패로 보고합니다.
3. 동일 캐릭터명은 기존 캐릭터에 연결하고 없는 캐릭터만 추가합니다. 기존 비어 있지 않은 값, 대표 캐릭터와 사진은 자동 변경하지 않습니다. 변경은 기존 관리자 수정 화면을 사용합니다.
4. 길드 참조 오류·잘못된 선택값·잘못된 URL·수식 등은 구체적인 오류로 보고합니다. 실패 행은 병합에서 제외합니다. 중복 업로드는 같은 정보를 재등록하지 않습니다.
5. `성공 항목 병합 승인`을 눌러야 반영됩니다. 승인 전 원본 JSON 백업을 내려받으며 기존 `forever-azeroth-v1` 키에 저장합니다. 다른 탭에서 데이터가 바뀌었으면 재검수를 요구합니다. 저장 실패 시 메모리 상태를 되돌립니다.
6. `fa-favs`, BGM 저장값, 슬롯, 이벤트·연대기·제보 및 원래 데이터의 미지 필드는 변경하지 않습니다.

**중요한 공개 범위:** 기존 사이트에는 로그인·서버 DB가 없습니다. 엑셀로 병합한 정보는 현재 브라우저에서 도감·검색·상세 화면에 즉시 반영되지만 다른 방문자의 브라우저로 전파되지 않습니다. 이 작업은 기존 저장 방식을 임의로 바꾸거나 현재 운영 데이터를 수집·삭제하지 않습니다. 전체 방문자에게 공개하려면 인증된 서버 저장 또는 별도의 공개 데이터 배포 설계가 필요합니다. 백업/조회 요청 파일에는 현재 브라우저의 등록 정보만 포함됩니다.

웹 열람 도구로도 5개 페이지에서 프로필 메타데이터를 읽지 못했습니다. **실제 프로필 조회 성공 0건, 미확인 5건**입니다. 시험 계정은 `sync/pilot-requests.json`에만 있고 홈페이지의 모험가 데이터로 등록하지 않습니다.

공식 [SOOP 공지](https://sotong.sooplive.com/?b_no=9999&board_type=servicenotice&check_content=true&check_title=true&page=2&work=view)의 검색 색인에는 API별 Public/Consent Scope 체계가 설명되어 있습니다. Public이라는 명칭만으로 모든 API의 무인 대량 수집이나 사진 재사용 권한이 생긴다고 해석하지 않습니다. [Open API 문서](https://openapi.sooplive.co.kr/apidoc), [개발자 포털](https://openapi.sooplive.com/), [서비스 약관](https://www.sooplive.com/policy/policy1.html)의 현재 상세 본문 및 프로필 이미지 이용 조건은 이 환경에서 확인하지 못했습니다. 공식 프로필 조회 엔드포인트, 인증 방식, 허용 Scope와 외부 사이트 링크/캐시 허용 여부를 **확정하지 않았습니다**.

따라서 자동 수집은 기본 비활성입니다. 비공식 웹 API·DOM 스크래핑·추측한 LOGO 경로·방송 썸네일로 우회하지 않습니다. URL을 연결하는 방식도 재사용 권한이 자동으로 허용된다고 간주하지 않습니다.

## 관리자 승인형 사진 동기화 (현재 설정 대기)

아래 실행 기반은 구현·오프라인 검증했지만 실제 API 연결은 미완료입니다. `sync/soop-provider.json`은 비활성 상태이고 임의 엔드포인트가 들어 있지 않습니다.

1. SOOP 개발자 앱에서 공식 프로필 API 문서, 필요한 권한과 이용 조건을 확인합니다. 계정 ID와 실제 방송국 프로필 이미지 필드가 있는 응답이어야 합니다. 해당 API가 제공되지 않으면 이 자동화 방식은 사용하지 않습니다.
2. 검토 근거 URL/승인 기록, HTTPS 공식 Open API 엔드포인트와 정확한 응답 필드를 공급자 설정에 명시합니다. 인증 헤더는 확인된 공식 문서에 맞춰 `secretHeaders`에 `{ "헤더명": { "env": "SOOP_API_TOKEN", "prefix": "문서상 접두어" } }` 형태로 설정합니다. 헤더명·접두어를 추측하지 않습니다. 토큰은 GitHub Secrets에만 보관합니다.
3. 저장소 Settings → Environments에 `soop-profile-sync`를 만들고 **Required reviewers**를 설정합니다. 환경 변수 `SOOP_SYNC_APPROVED=true`는 검토 완료 후에만 설정합니다. 이 변수만으로 Required reviewers가 자동 구성되지는 않습니다. 현재 저장소의 환경 설정·Secrets는 변경하지 않았습니다.
4. GitHub의 `Review SOOP profile URLs` workflow를 `pilot`으로 수동 실행합니다. 이 기능을 아직 main에 배포하지 않았으므로 기본 브랜치에서 바로 실행할 수 있다고 보장하지 않습니다. 승인된 테스트 저장소/브랜치에서 운영 검토 후 실행합니다. 먼저 제공된 5개 계정 모두의 실제 프로필 조회가 성공해야 합니다.
5. 결과 아티팩트에서 원본 방송국과 사진을 관리자 눈으로 확인합니다. 성공한 보고서를 `sync/reviews/` 아래에 커밋합니다. 공급자 설정이 바뀌면 시험을 다시 해야 합니다. 보고서는 같은 설정으로 7일 이내 생성된 5개 성공 결과여야 합니다.
6. 관리자에서 사진이 없는 모험가만 `사진 조회 요청 JSON 다운로드`로 내보냅니다. `sync/requests/` 아래에 요청 파일을 올리고 `batch` 수동 실행 시 요청 경로와 시험 보고서 경로를 지정합니다. 인원을 150명으로 제한하지 않습니다. 작업 시간 제한은 90분이므로 매우 큰 명단은 나누어 실행합니다.
7. 결과 JSON은 아티팩트로만 생성되며, workflow는 웹사이트 데이터나 main을 수정하지 않습니다. 관리자에서 결과 JSON을 업로드하고 **프로필 원본 URL** 연결 결과를 검수·승인해야 사진이 적용됩니다. 기존 사진이 있으면 `중복 / 기존 사진 유지`, 이미지가 없으면 `이미지 없음`, 요청 오류는 `실패`로 표시합니다. 기본 이미지와 수동 URL 등록을 유지합니다.

조회기는 요청 간격 최소 2초, 일시 오류 2회 재시도(총 3회), 429 Retry-After(최대 60초), 최대 24시간 URL 캐시, 중복 요청 제거를 적용합니다. 401/403 뒤에는 추가 외부 요청을 중단합니다. 계정 ID 응답 일치와 프로필 전용 이미지 경로를 확인하며 이미지 바이트는 저장하지 않습니다. HTTP 리디렉션·비 HTTPS·다른 호스트는 허용하지 않습니다. 현재 허용 목록은 SOOP 공식 Open API 호스트와 프로필 이미지 호스트뿐입니다. API가 다른 공식 CDN을 반환하면 문서·이용 조건 확인 후 검수하여 허용 목록과 테스트를 수정해야 합니다.
