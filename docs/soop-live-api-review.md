# SOOP LIVE 연동 권한 조사

조사일: 2026-10-22. 작업 브랜치: `feat/admin-xlsx-soop-profiles`.

## 결론

**권한 확인 전까지 LIVE API 연동을 보류합니다.** 실시간 데이터 수집을 위해 API를 호출하거나 토큰을 발급·수집하지 않았습니다. LIVE 메뉴의 기존 책 디자인, 방송 상태 미연동 안내, 모험가 정보, SOOP 외부 이동 링크를 유지합니다. main 및 운영 배포는 변경하지 않습니다.

## 사용자가 제공한 API 정보

- `POST https://openapi.sooplive.com/validate/live/status`
- `access_token` 필수
- 응답: `status` (`streaming` / `streamend`), `broad_title`, `current_view_cnt`, `broad_cate_no`, `broad_thumb`, `link`, `broad_start`

위 목록은 사용자가 전달한 정보입니다. 이번 환경에서 공식 응답 스키마를 독립적으로 확인한 결과와 구분합니다. 응답 항목이 풍부하더라도 조회 대상과 접근 권한까지 확인되는 것은 아닙니다.

## 확인한 근거와 접근 제한

[SOOP 공식 오픈 API 개편 공지](https://sotong.sooplive.com/?b_no=9999&board_type=servicenotice&check_content=true&check_title=true&page=2&work=view)의 검색 색인에는 다음 내용이 있습니다.

- 애플리케이션에서 선택한 Scope에 해당하는 API/SDK만 이용할 수 있습니다.
- Public은 별도 승인 절차 없이, Consent는 사전 승인 절차를 거쳐 사용하는 권한 구분입니다.
- OAuth 동의 화면에 애플리케이션이 사용할 범위가 표시됩니다.

이는 API별 인증 요건과 타인 계정 조회 권한을 대신하는 설명이 아닙니다. Public을 ‘익명 호출 가능’으로, 관리자 OAuth 로그인을 ‘다른 모든 방송인 조회 허용’으로 해석하지 않습니다.

[공식 broad-watch 문서](https://developers.sooplive.co.kr/docs/api/broad-watch)와 [broad-stream 문서](https://developers.sooplive.co.kr/docs/api/broad-stream)는 웹 열람 도구에서 본문을 얻지 못했습니다. 앞선 직접 접근도 환경 프록시의 CONNECT 403으로 차단됐습니다. 공식 도메인을 대상으로 방송 상태, 방송 목록, 사용자/방송국 조회, 인증 및 API 경로를 추가 검색했으나 접근 가능한 공식 상세 명세를 확보하지 못했습니다. 비공식 라이브러리·팬사이트의 작동 사례는 SOOP의 공식 이용 허가를 증명하는 자료로 사용하지 않았습니다.

이 실패는 API가 없거나 SOOP가 특정 계정의 접근을 거절했다는 뜻이 아닙니다. 현재 환경에서 공식 문서를 검증하지 못했다는 뜻입니다. 검증되지 않은 엔드포인트를 다른 도메인·비공식 웹 인터페이스로 우회 호출하지 않았습니다.

## 요청한 네 가지 질문

| 질문 | 확인 결과 |
|---|---|
| 방송인 본인의 OAuth가 필수인가? | 미확인. 토큰이 필요한 것은 전달받았으나 해당 토큰의 주체와 조회 대상 관계를 공식 명세로 확인하지 못했습니다. |
| 관리자 토큰 하나로 다른 방송인들을 조회할 수 있는가? | 허용 근거 미확인. 관리자 토큰을 여러 방송인 ID에 사용해 보며 권한을 시험하지 않습니다. |
| 제3자 방송 상태를 조회하는 별도의 공식 API가 있는가? | 접근 가능한 공식 문서에서 확인하지 못했습니다. 그런 API가 없다고 단정하지 않습니다. |
| 등록된 150명 이상을 인증 없이 조회하는 공식 방법이 있는가? | 확인하지 못했습니다. 인증 여부뿐 아니라 조회 대상 범위·호출 한도·표시 및 캐시 조건도 미확인입니다. |

관리자가 150명을 직접 등록했다는 사실은 SOOP API의 타인 계정 조회 권한을 부여하지 않습니다. 응답에 `user_id`가 있거나 요청에 대상 ID 필드가 있다고 해도, 그 자체로 임의 계정 조회가 허용된다는 뜻은 아닙니다. 반대로 토큰이 필수라는 사실만으로 방송인별 OAuth가 반드시 필요하다고 단정하지도 않습니다.

## 연동을 진행하기 위해 필요한 공식 근거

1. 요청 파라미터 전체와 조회 대상 지정 방식, 응답의 계정 식별 정보.
2. 토큰 종류/발급 흐름, 필요한 Scope, 타인 계정 조회 허용 범위. 관리자 또는 앱 토큰만으로 가능한지 명시되어야 합니다.
3. 별도 방송 목록/공개 상태 API가 있다면 해당 공식 문서와 인증·필터·페이지 이동 방식.
4. 150명 이상 조회를 위한 앱별/사용자별 호출 한도, 캐시·저장 허용 기간, 썸네일 외부 표시 조건.

이 정보가 확인되면 최소 계정으로 검증한 뒤 전체 명단으로 확장합니다. 모든 버튜버에게 개별 OAuth를 요청해야 하는 API만 제공된다면, 개별 인증을 피하려는 팬사이트 요구에 맞는 방법으로 간주하지 않습니다.

## 허용된 방법이 확인된 뒤의 구현 기준

- 기존 LIVE 카드와 외부 이동 방식을 보존하고 실제 상태·방송 썸네일·제목·시청자 수·카테고리만 연결합니다.
- `broad_thumb`는 방송 카드용입니다. 모험가의 방송국 프로필 사진으로 재사용하지 않습니다.
- 카테고리 번호의 이름 매핑은 공식 목록을 확인하고, 확인하지 못한 이름을 임의로 만들지 않습니다.
- 요청 실패·토큰 만료·시간이 지난 데이터는 ‘미확인’으로 처리합니다. 오류를 방송 종료로 표시하지 않습니다. 마지막 확인 시각을 제공합니다.
- 토큰은 HTML·브라우저 localStorage·공개 JSON·GitHub 커밋에 넣지 않습니다. 현재 GitHub Pages에는 비밀을 보관할 서버가 없으므로 허용된 서버/수집 작업과 공개 결과를 분리해야 합니다.
- 공식 한도에 맞는 요청 간격·재시도·공유 캐시를 적용합니다. 스케줄 작업을 쓰는 경우 그 주기를 실시간이라고 과장하지 않습니다.

이 문서는 조사 기록이며 아직 검증된 LIVE 공급자 설정이나 구현 완료 보고가 아닙니다. 기존 엑셀 등록과 수동 사진 등록은 별개로 구현되어 있으며, 이 조사 때문에 데이터나 저장 구조를 변경하지 않았습니다.
