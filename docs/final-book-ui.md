## 구현과 데이터

- `final-book.js`는 기존 아카이브·관리자 기능 위에 화면을 적용한다. `app.js`의 데이터 키, 저장 형식, 관리자 편집, 백업/복원과 제보 기능을 유지한다.
- 시안의 사람·길드·수치·방송 상태를 데이터로 등록하지 않는다. 빈 아카이브에는 빈 상태를 표시한다. 기존에 저장된 레코드를 삭제하거나 정리하지 않는다.
- 기존 최소 seed(우왁굳 1명)도 유지한다. 대상 브랜치에서 이미 제거한 예시 자동 등록을 되살리지 않는다.
- 직업·종족·길드 복합 필터, 검색 입력과 커서 유지, 이름/레벨/등록순 정렬, 격자/목록 보기, 펼침 단위 페이지 이동을 지원한다.
- 상세 팝업에 다른 캐릭터와 이전 시즌 기록을 유지한다. Escape, 닫기, 배경 클릭, 키보드 초점 제한을 지원한다.
- SOOP 실시간 API는 기존과 같이 미연동 상태다. LIVE 표시나 시청자 수를 만들어 내지 않는다.
- 관리자 인증과 서버 저장은 기존 구현 범위 그대로이며, 데이터 저장은 현재 브라우저의 localStorage를 사용한다.

## 에셋

`assets/wapobook/final-atlas.webp` (335,566 bytes): 시안을 참고해 제작한 빈 책·금장·보석·가죽, 항구 배경, 로고. CSS의 위치와 크기로 필요한 영역만 표시한다.

`assets/wapobook/torn-parchment.webp` (142,650 bytes): 상세 팝업용 찢어진 양피지. 두 새 에셋의 합계는 약 467 KiB다. 원본 생성 PNG는 배포하지 않는다.

기존의 화면별 JPG 배너와 SVG 길드 깃발·양피지·금장도 재사용한다. 인물 사진은 실제 등록 레코드의 이미지 URL을 사용한다.

## 빌드와 검증

이 저장소는 번들러가 필요 없는 정적 사이트다. Node와 Python 3이 필요하다.

```sh
python3 scripts/build.py
python3 -m http.server 4173
# 다른 터미널에서 (Python playwright와 /usr/bin/chromium 필요)
python3 scripts/test_book_ui.py
```

빌드는 두 JavaScript 파일의 구문, HTML과 최종 CSS의 로컬 참조를 검사하고 배포할 파일만 `dist/`에 복사한다. `dist/`는 커밋하지 않는다. 원래와 같이 저장소 루트도 정적 호스팅 가능하다.

브라우저 검증은 독립된 임시 Chromium 컨텍스트에만 테스트 레코드를 만든다. 저장소의 `data/` 파일이나 사용자의 브라우저 데이터를 변경하지 않는다. 전체 경로, 복합 필터, 검색 커서, 정렬, 페이지 경계, 즐겨찾기, 팝업, 소식·이벤트·연대기, 관리자 수정 및 새로고침 후 저장, 다른 캐릭터 정보, 390/768/1024px 가로 넘침, JavaScript 오류를 검사한다.
